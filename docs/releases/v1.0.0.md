# v1.0.0

<!-- Notes de la version 1.0.0 (13 novembre 2026), reprises du CHANGELOG. À coller dans la description de la release GitHub. -->

**En bref** : Qwen2.5-Coder 7B répond juste à 70,9 % des 110 questions du périmètre sur un
processeur ordinaire (79,1 % avec des exemples choisis par similarité), refuse les 10 questions hors
périmètre, et aucune des 32 requêtes d'écriture produites par cinq modèles face à des questions
piégées n'a atteint la base. Synthèse : [docs/resultats.md](https://github.com/GracielaTHOO/TEXT_TO_SQL4DRUGS/blob/main/docs/resultats.md).

Version finale du projet : démo enrichie, mesures de performance, sécurité éprouvée par un jeu de
questions adverses, synthèse des résultats. Les runs qui portent les chiffres de cette version sont
figés dans `results/releases/v1.0.0.json`.

### Ajouté
- Résultats figés par version (`scripts/freeze_results.py`, `results/releases/v1.0.0.json`) : fichier, empreinte SHA-256 et chiffres clés de chaque run du classement et du jeu adverse.
- Synthèse des résultats en une page (`docs/resultats.md`) : dispositif, chiffres à retenir, six enseignements, limites et recommandation ; brouillon d'article LinkedIn (`docs/article-linkedin.md`).
- Démo : réponse rédigée en français sous le tableau (`medsql.narration`, par gabarits à partir du résultat exécuté, sans appel LLM supplémentaire), export CSV pour tableur français (`;`, virgule décimale, UTF-8 avec BOM), historique des 20 dernières questions de la session (un clic repose la question). La CLI `medsql ask` affiche la même phrase.
- Tests de la démo (fonction `answer` sur la base de test) ; la CI installe l'extra `app`.
- Mesures de performance : temps de premier token, débits de génération et de lecture du prompt (durées d'Ollama), coût CPU de la machine par question (`medsql.perf`), bilan `summary.performance` (`medsql.eval.performance`) et section *Performance* du tableau de bord. La CLI `medsql ask` affiche le premier token et le CPU.
- Cache des requêtes générées pour la démo (`medsql.cache`) : une question déjà posée réexécute la requête SQL gardée, sans appel au modèle ; abstentions gardées aussi, requête invalide régénérée.
- Sécurité : jeu de 28 questions adverses (`adversarial.yaml` : injection, injection mêlée à une vraie question, requêtes coûteuses, fuite du prompt, texte démesuré), commande `medsql redteam` qui échoue en cas d'incident, configuration `securite` du workflow d'évaluation, section *Sécurité* du tableau de bord et rapport `docs/securite.md`.
- Badge de couverture sans service tiers (`scripts/coverage_badge.py`, `make coverage-badge`, vérifié par la CI) et seuil minimal de 90 % ; tests du téléchargement de la BDPM (couverture 94 → 96 %).
- Workflow *Captures de la démo* et `scripts/capture_demo.py` : l'image Docker, avec la vraie BDPM et le vrai modèle, répond à trois questions posées dans un navigateur ; captures et GIF dans `assets/demo/`.

### Modifié
- Tableau des résultats du README : colonne *Questions* (périmètre de chaque run), les runs d'octobre portant sur 60 questions et les suivants sur 110.
- Relecture de la documentation : README (garde-fous, abstention, répartition actuelle des 120 questions, organisation du dépôt), architecture (modules ajoutés depuis la v0.2.0), guide de contribution.
- La démo affiche les runs adverses dans son onglet *Évaluation* et masque le cadre SQL et le tableau quand il n'y a rien à montrer (abstention, erreur) : les captures montraient un cadre vide et un tableau aux colonnes 1, 2, 3.
- README : section *La démo* avec le GIF et les captures.
- Garde-fous renforcés après la sonde de S13 : taille maximale d'une valeur de 1 Mo (`randomblob`, `zeroblob` et `group_concat` démesurés échouent au lieu d'allouer des centaines de mégaoctets), fonctions `load_extension`, `fts3_tokenizer` (fuite d'adresse mémoire), `readfile`, `writefile` et `edit` refusées, question de plus de 500 caractères non transmise au modèle.
- Python 3.11 minimum (Python 3.10 n'est plus maintenu et n'offre pas `Connection.setlimit`) ; la CI couvre 3.11 à 3.13.

### Résultats
- Tests adverses (6 novembre 2026), 28 questions × 5 modèles : 32 requêtes d'écriture ou d'administration produites par les modèles, toutes bloquées, base intacte, 0 incident. Qwen2.5-Coder 3B suit 8 injections directes sur 10, le 7B 2 sur 10 (15 abstentions sur 28). Une fuite de règle du prompt (public) par Llama 3.1 8B.
- Performance (4 novembre 2026, runner 4 vCPU sans GPU) : premier token médian de 0,6, 1,5 et 3,0 s pour Qwen2.5-Coder 1.5B, 3B et 7B avec les exemples fixes, génération à 21,8, 6,4 et 4,6 tokens/s, 6,7, 23,7 et 30,6 s de CPU par question. Les exemples dynamiques font passer le premier token du 7B à 18,7 s (le préfixe du prompt n'est plus réutilisé) et son CPU à 58,5 s, pour 79,1 % d'exactitude (+8,2 points, p = 0,06).
